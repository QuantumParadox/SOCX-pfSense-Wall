# SOCX v0.6 Incident Cockpit

SOCX v0.6 turns the browser dashboard into a small read-only incident cockpit while preserving the terminal wall layout.

## Highlights

- Browser Incident Cockpit panel with top blocked sources, destination ports, DNSBL domains, affected LAN hosts, and IDS signal.
- Safe Commander buttons in `socweb` for `status`, `incident`, `snapshot`, `zeek`, and `Pi AI`.
- `/api/commander` POST endpoint with a fixed command allowlist only. It does not expose arbitrary shell execution.
- `socx snapshot-cron install|remove|status` for nightly evidence snapshots with retention cleanup.
- Snapshots now include `incident.json`, `top-talkers.json`, `incident-mode.txt`, `zeek-health.txt`, and `SHA256SUMS`.
- `socx-doctor zeek --archive-reviewed` archives reviewed Zeek crash folders with checksums before removing them from the live Zeek tmp path.
- pfSense-to-Pi LLM exports now include Incident Mode and top-talker context so the Pi 3-LLM dashboard can reason from richer evidence.
- Terminal wall Threat Pulse can rotate Incident Mode pressure without changing the successful btop-style layout.

## Safety Model

SOCX remains read-only by default. The Commander buttons run diagnostic and evidence-preservation commands. Zeek crash folder cleanup is intentionally a separate reviewed archive command.

## Useful Commands

```sh
socx snapshot-cron install
socx snapshot
socx incident-mode 120
socx-doctor zeek
socx-doctor zeek --archive-reviewed
socx pi-llm
```

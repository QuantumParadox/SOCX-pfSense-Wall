# SOCX v1.1.0 Daily Story

SOCX v1.1.0 adds a Daily Story layer on top of the existing wall, browser dashboard, and terminal tools. It does not change firewall policy. It turns the live read-only evidence SOCX already collects into a plain-English narrative an operator can read from the wall or preserve for later review.

## Added

- `/story` browser detail page.
- `/api/story` JSON endpoint.
- `/api/story-archive` one-click archive endpoint.
- `socx story` terminal command.
- `socx story archive` text and JSON preservation under `/root/socx-stories/`.
- Browser Commander `Story` action.
- Voice Commander routing for “story” and “daily story.”

## What The Story Uses

- Data Truth freshness score and reason.
- Autopilot mode and score.
- Top firewall source/port pressure.
- DNSBL activity.
- IDS high-signal versus routine/watch signal.
- Direct and VPN Speedtest history.
- Repeated-event memory.
- Pi fleet and Pi AI role status.
- What Changed timeline.

## Safety

Daily Story is read-only. It recommends review steps such as opening `/why`, `/health`, or preserving an incident bundle, but it does not change pfSense rules, DNSBL lists, IDS suppression, VPN config, or gateway policy.

## Upgrade

```sh
git pull
sh install-pfsense.sh
service socxweb restart
socx story
```

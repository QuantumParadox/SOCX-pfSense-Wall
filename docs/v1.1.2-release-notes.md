# SOCX v1.1.2 Hardware Trend And Stability Watch

This release makes SOCX smarter about the upgraded pfSense appliance hardware and gives operators a clean way to prove stability over time.

## Highlights

- `socx hardware` shows CPU model, core/thread count, hottest core, Celsius/Fahrenheit temperature, thermal headroom, AES-NI, powerd, temperature trend, and UPS watt trend.
- `socx stability-watch <seconds> <interval>` records bounded JSONL stability samples and writes a short summary under `/root/socx-stability/`.
- `socx baseline` writes a performance baseline under `/root/socx-baselines/` with system, CPU, BIOS, Speedtest, readiness, Daily Story, and hardware evidence.
- Autopilot now includes hardware health in its security watch score and summary.
- Browser `/health`, `/story`, and `/speedtest` now show hardware trend/headroom and VPN crypto headroom.
- `socx v1-check` now reads Pi fleet JSON without requiring `jq`, fixing false `2/0 online` style warnings.

## Useful Commands

```sh
socx hardware
socx stability-watch 3600 30
socx baseline
socx history append
socx history trend 20
socx v1-check
socx status
```

## Live Validation From The Release Appliance

The release was validated on a Lenovo ThinkCentre M910t running an Intel Core i7-7700 in pfSense Plus:

- `socx v1-check`: `OK=16 WARN=0 FAIL=0`
- `socx status`: `OK=19 WARN=0 FAIL=0`
- Short stability watch: `PASS`, 4 samples, 0 errors
- Pi fleet: `2/2 online`
- Pi 3-LLM roles: `3/3 online`
- Browser `/api/state` and `/api/story`: reachable
- Wall renderer error log: clean

## Notes

SOCX remains read-only for firewall/security policy. These additions collect evidence, trend health, and improve operator visibility; they do not auto-change pfSense firewall rules, DNSBL policy, IDS suppressions, or VPN routing.
